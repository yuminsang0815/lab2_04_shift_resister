# LAB 2 시프트 레지스터 실험 전 레포트

## 1. 제어 입력별 다음 상태 표 및 값 변화 계산 과정
| rst | enable | 다음 `value[3:0]` 상태 |
| :---: | :---: | :--- |
| 1 | 무관 | `0000` (초기화) |
| 0 | 0 | 이전 `value` 유지 |
| 0 | 1 | `{serial_in, 이전 value[3:1]}` |

* **값 변화 계산 과정 (8 -> 4 -> A -> 5):** 
  시프트 레지스터는 Non-blocking 할당(`<=`)과 배열 이어붙이기 연산(`{}`)을 사용해 구현됩니다. `serial_in` 입력은 최상위 비트(MSB, `value[3]`)로 진입하고 나머지는 오른쪽(LSB)으로 이동합니다.
  1. **초기값:** `value` = `0000`
  2. **첫 번째 에지 (`serial_in=1`):** `value` = `{1, 000}` = `1000` (16진수 `8`)
  3. **두 번째 에지 (`serial_in=0`):** `value` = `{0, 100}` = `0100` (16진수 `4`)
  4. **세 번째 에지 (`serial_in=1`):** `value` = `{1, 010}` = `1010` (16진수 `A`)
  5. **네 번째 에지 (`serial_in=0`):** `value` = `{0, 101}` = `0101` (16진수 `5`)

## 2. 파일별 역할 설명
* **RTL (`shift_register4.v`, `input_frontend.v`, `lab2_shift_register.v`):** 비동기 스위치와 버튼 입력을 디바운싱/동기화하고, 이를 `enable` 및 데이터 입력 신호로 받아 4비트 시프트 연산을 수행하는 전체 하드웨어 논리 설계 파일입니다.
* **TB (`tb_shift_register4.sv`):** 작성한 시프트 레지스터 모듈이 올바른 시프트, 유지, 초기화 연산을 수행하는지 자가검사(Self-Checking)하는 시뮬레이션용 테스트벤치입니다.
* **`simulation.json`:** VS Code에서 Icarus 시뮬레이터가 컴파일 및 실행해야 할 RTL, TB 소스 목록 및 시뮬레이션 최상위 모듈을 선언하는 설정 파일입니다.
* **XDC (`lab2_shift_register.xdc`):** Vivado 구현을 위해 FPGA 칩의 I/O 핀 번호(클록 B6, 리셋 K4 등), 전압 규격(LVCMOS33), 클록 주기(1 kHz)를 설정하는 물리 제약조건 파일입니다.

## 3. 정상/변경/원복 실행 로그 및 기대값 비교 분석
시프트 방향을 반대로 뒤집는 오류를 삽입(`{value[2:0], serial_in}`)하여 동작을 확인한 결과입니다.
* **[정상](../../evidence/04/vscode/simulation.txt):** `LAB2_PASS shift_register4 checks=8`, 종료 시각: 106 ns 통과.
* **변경 (오류 발생):** 16 ns 시점에서 `LAB2_FAIL input enters MSB time=16000` 발생 및 시뮬레이션 $fatal 중단.
  * **원인 해석:** 정상 동작에서는 첫 입력 `1`이 MSB에 들어가 기대값이 `4'b1000`(8)이어야 하지만, 코드를 수정하여 입력이 LSB로 들어가게 되어 실제값이 `4'b0001`(1)이 도출되어 불일치가 발생했습니다.
* **원복:** 코드 정상 복구 후 재실행 시 8개의 검사가 모두 통과하여 `checks=8`, 종료 시각: 106 ns로 정상 동작을 재확인했습니다.

## 4. 파형 분석
> **[ VaporView 전체 파형 ](../../evidence/04/vscode/wave.png)**
* **전체 흐름 분석:** 시뮬레이션 시작 후 `serial_in` 신호가 1 -> 0 -> 1 -> 0 순서로 인가되며, 이에 따라 `value` 값이 8 -> 4 -> A -> 5로 정상적으로 한 칸씩 시프트 되는 것을 확인했습니다.
* **enable 유지 구간 해석:** 35 ns 시점에서 `serial_in`은 1이지만 `enable`이 0이므로 값이 시프트 되지 않고 이전 값 `4`를 그대로 유지합니다. `enable` 신호가 시프트의 활성화 조건임을 확인할 수 있습니다.
* **리셋 우선 구간 해석:** 105 ns 시점에서 `enable=1`, `serial_in=1`이 입력되었으나, 동시에 `rst=1`이 함께 걸렸습니다. 시프트 레지스터의 조건문에서 리셋(`rst`)이 우선순위를 가지므로 106 ns 검사 시점에 값이 `0`으로 비동기 우선 초기화되는 것을 확인했습니다.

## 5. 보드 조작에 따른 예상 LED 상태
보드에서 SW1(sw[7])은 `serial_in`, N8(button)은 `enable`, K4(rst)는 비동기 리셋 입력으로 작용합니다.
* **K4 버튼 누름:** 시프트 레지스터 강제 초기화. **(예상 LED: `00`)**
* **SW1=1 설정 후 N8 클릭:** 입력 `1`이 MSB 진입. **(예상 LED: `08`)**
* **SW1=0 설정 후 N8 클릭:** 입력 `0` 진입, 기존 비트 시프트. **(예상 LED: `04`)**
* **SW1=1 설정 후 N8 클릭:** 입력 `1` 진입, 기존 비트 시프트. **(예상 LED: `0A`)**
* **SW1=0 설정 후 N8 클릭:** 입력 `0` 진입, 기존 비트 시프트. **(예상 LED: `05`)**
* **SW1=0인 상태로 N8 4번 연속 클릭:** 0이 계속 진입하여 기존 데이터를 모두 밀어냅니다. **(예상 LED: `02` -> `01` -> `00` -> `00` 유지)**
